## Models and migration

`src/models/collector_run.py` defines CollectorRunORM: id, source, started_at, finished_at, status, received_count, new_count, duplicate_count, cross_source_duplicate_count, failed_count, duration_ms, error and created_at. Timestamps are timezone-aware. The initial status is running; terminal statuses are success, failed and skipped. Running also exposes interrupted processes rather than inventing a terminal result. Counts are retained on partial database failures. Only sanitized error types or fixed skip reasons are stored.

`src/models/digest_run.py` contains the existing DigestRunORM. Its unique (user_id, local_date) reservation, statuses and delivery columns remain intact. New fields are metrics_recorded, candidate_count, filter_rejected_count, accepted_count, score_0_49_count, score_50_59_count, score_60_69_count, score_70_79_count, score_80_89_count, score_90_100_count and below_threshold_count. ORM aliases selected_count, sent_count and failed_count use the original selected, sent and failed database columns. Shared timestamp declarations moved to timestamps.py.

Migration `9f28bc7d43a6`, following `54383f510932`, was autogenerated, reviewed and applied. It creates collector_runs and adds only telemetry columns to digest_runs. ## Definitions and limits

- All period windows are half-open UTC intervals. Collector/digest runs use started_at; jobs and notifications use created_at; feedback uses updated_at. User counts describe the current snapshot.
- Collector received/new/duplicate counters are measured per invocation. Cross-source duplicates are a subset of fingerprint duplicates, identified by a different stored source. Received counts start at collector DTOs; parser-level omissions are not retroactively counted.
- New/run = new / (successful + failed runs). Skipped and running runs are excluded. Duplicate rate = duplicates / received.
- Digest candidate/filter/score totals cover measured runs only. Accepted jobs are scored once, bucketed before threshold/cap selection, and may occur in multiple user/day runs. Unmeasured runs are displayed separately; if all runs are unmeasured, selection and score output is N/A. Historical selection outcomes cannot be reconstructed reliably.
- Digest failed cards include unexpected card-processing exceptions. Summary failure counts as a failed run without counting unattempted cards as failures. Notification aggregates independently reflect stored sent/failed/pending outcomes.
- Filter rejection rate = rejected / candidates. Notification success rate = sent / (sent + failed), excluding pending. Save/reject rates = feedback / sent notifications. Feedback is the latest state updated in the interval, not a click history. Feedback on older cards can make these period ratios exceed 100%.
- Zero denominators return None in schemas and N/A in Telegram. Trial, Premium and Free partition all users; active users are an independent count.
- Salary completeness requires a positive salary bound; 0–0 does not count. Region requires nonempty remote_regions. Timezone requires nonblank timezone_text or an explicit offset, including zero. Technologies requires a nonempty array. These measure field presence, not data correctness. Free-form location is not reinterpreted as remote eligibility.
- Filter reasons are not persisted by the existing pipeline; no per-job analytics event log was added.
